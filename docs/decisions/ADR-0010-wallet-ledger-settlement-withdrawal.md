# ADR-0010 — 錢包記帳、T+N 分潤結算與人工提現

Status: Accepted
Date: 2026-09-30

## Context

ADR-0009 讓每筆訂單在下單時留下各層手續費快照，但錢沒有落點：商戶實收、代理分潤、平台收入都只停在報表。競品（見 ADR-0009 的 PRD 連結）與本專案原本的「錢包與提現（規劃中）」佔位畫面都假設平台代收款項，商戶與代理的餘額累積在平台上，再主動申請提現。

限制條件：
- 目前沒有任何代付（轉帳）通道；黑貓 PAY 只開放 ibon 代收（AGENTS.md）。
- 不修改 PayOrder 狀態機與下單／回調流程（RED）。
- 所有金額為新臺幣「分」（ADR-0004）。

使用者於 2026-09-30 指示「直接全部做完，只有必須本人處理的才列清單」，以下決策由實作者依競品慣例決定，金額相關參數都可在系統配置調整。

## Decision

1. **帳戶與流水**
   - `t_wallet_account` 以（擁有者類型, 擁有者ID）唯一。類型有 MCH、AGENT、PLATFORM（平台收入）、CHANNEL（上游渠道成本，以 ifCode 區分）。
   - 可用餘額與凍結金額分兩個桶。
   - 所有異動只能經 `WalletService.post` 進行：先鎖帳戶列，再寫 `t_wallet_ledger`，最後以增量更新餘額。
   - 流水以（帳戶, 業務類型, 業務單號）唯一，重跑不會重複入帳。
   - 恆等式：每個帳戶的流水加總等於目前的可用加凍結。
2. **結算**
   - 營運平台每 5 分鐘執行一次排程，也可手動按「立即結算」。
   - 只結算同時符合三個條件的訂單：有快照、支付成功、成功時間早於截止點。截止點為 T+N（`walletSettleDelayDays`，預設 1，以台北午夜計）。
   - 一筆訂單的金額全數分配：
     - 商戶：金額減商戶手續費
     - 高級代理：高代費
     - 直屬一般代理：代理費
     - 推薦人：推薦佣金
     - 渠道：渠道費
     - 平台：其餘部分
   - 各份合計恆等於訂單金額；同一帳戶出現多次時合併為一筆。
   - 以快照的 `settle_state` 條件更新搶佔，保證只結算一次。
   - 已結算後全額退款的訂單反向沖回；結算前就退款的標記為不結算。
   - 沒有快照的舊訂單不結算（沿用既有方式）。
3. **提現**
   - 商戶與代理自行設定收款帳戶，再申請提現。申請帶冪等鍵 `reqNo`，申請時凍結金額。
   - 平台人工匯款後標記「已撥款」並填匯款單號，這時才出帳；手續費（`withdrawFeeAmount`）記入平台帳戶。
   - 駁回（必填原因）或申請人取消時解凍。
   - 審核以「待審核」狀態的條件更新進行，不會重複處理。
   - 沒有代付通道，所以不做全自動代付；需要時另立 ADR。
4. **風控**
   - 提現時比對黑名單 `t_risk_blacklist`（收款帳號、戶名），範圍為全平台或高級代理的轄區。命中即拒絕，留下已駁回紀錄，不凍結金額。
   - 以下情況只標記提示，交由審核人判斷：
     - 同一帳號當日次數過多
     - 限制銀行代碼
     - 收款帳戶 24 小時內剛變更
5. **人工調帳**：用於更正或補償。申請人不得自行核准，須另一人覆核後才記帳。
6. **推薦佣金**（補充 ADR-0009）：新增第五層 `REFERRER`。規則設在推薦人代理上（任何層級都可以），也可由商戶覆寫。沒有推薦人時為 0，預設不收。
7. **下級費率**（補充 ADR-0009）：高級代理可在代理後台設定自己下級代理的代理費與推薦佣金。設定後若任何受影響商戶以 1000 元試算的各層合計超過其商戶費率，整筆回滾。

## Options Considered

- **單一可變 balance 欄位**：簡單，但無法稽核，也無法保證冪等。不採用。
- **在支付成功回調裡即時入帳**：延遲最低，但要修改 PayOrder 狀態機與回調（RED），且與 T+N 撥款慣例不符。不採用；改用排程掃描快照。
- **完整複式記帳（借貸分錄）**：更嚴謹，但現階段「每筆訂單各份加總等於訂單金額」加上「流水加總等於餘額」的兩個恆等式已足以對帳。保留日後升級的空間。

## Consequences

- 商戶、代理、平台的錢形成閉環：訂單、快照、結算、錢包、提現、撥款，每一步都有流水與操作者。
- 平台實際匯款仍在系統外完成；「已撥款」仰賴審核人填寫正確的匯款單號，對帳要以銀行明細核對 `paid_ref`。
- CHANNEL 帳戶代表應付上游的渠道成本；實際由上游在撥款時扣除，數字僅供對帳。
- 部分退款目前不沖回（ibon 代收沒有退款能力）；日後若開放退款，需要補上部分沖回。
