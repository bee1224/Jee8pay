# 前端多國語系（營運平台、商戶平台）

範圍：

- `jeepay-ui/jeepay-ui-manager`（營運平台，含平台、團長、隊長與子帳號；電腦版與手機版共用）。
- `jeepay-ui/jeepay-ui-merchant`（商戶平台）。沒有獨立的手機版畫面，手機寬度沿用原本的版面，頂部列的語言按鈕只顯示地球圖示。

兩個專案各有一份相同的 `src/i18n/index.ts` 與 `src/components/LanguagePicker/`，修改時兩邊一起改。字典各自獨立：商戶平台的字典沿用營運平台已翻好的句子，只收商戶平台用得到的鍵。

## 支援語言

| 代碼 | 名稱 | 字典 | 找不到時退回 |
| --- | --- | --- | --- |
| `zh-TW` | 繁體中文（預設） | 原文即鍵，無字典 | — |
| `zh-CN` | 简体中文 | `zh-CN.json` | 繁中原文 |
| `yue` | 粵語（香港） | `yue.json`（只列與繁中不同的句子） | 繁中原文 |
| `en-US` | English (US) | `en-US.json` | 繁中原文 |
| `en-GB` | English (UK) | `en-GB.json`（只列拼字差異） | `en-US` |
| `id` `ja` `ko` `vi` `th` `hi` `ru` | 印尼、日、韓、越、泰、印地、俄 | 各自 `.json` | 繁中原文 |
| `fil` | Filipino | `fil.json` | `en-US` |

Ant Design 元件文字與 dayjs 日期跟著切換；Ant Design 沒有菲律賓語，`fil` 的元件內建文字用英文。

## 運作方式

- 程式碼：`src/i18n/index.ts`。翻譯鍵就是繁中原文：`t('訂單管理')`、模板內 `$t('訂單管理')`；`{0}`、`{1}` 為參數。
- 啟動順序：`src/main.ts` 先 `initLocale()` 載入字典，再載入 `appMain.ts`。畫面模組在載入時就會呼叫 `t()`（例如表格欄位），字典必須先到位。
- 語言存在瀏覽器 `localStorage` 的 `jeepay-locale`（每台裝置各自設定，未設定為繁中）。
- 儲存後整頁重新載入（`saveLocale()`），選單、表格欄位、元件語系、日期格式一次全部換掉，不會有半新半舊的畫面。
- 切換入口：電腦版頂部列地球按鈕、登入頁右上角、營運平台手機版「我的 → 語言」。語言名稱一律用該語言自己的寫法。
- 字形：`global.less` 依 `html[lang]` 換 `--jp-font`（日文不落到繁中字形、泰文與印地文用對應字形）。

## 後端傳來的中文

後端與資料庫目前只有繁中，前端在顯示時轉換，資料庫內容不變：

- 選單名稱：`translateMenuTree()`，登入取得選單時轉換。
- 商戶平台首頁圖表：後端回傳的「收款」「退款」與支付方式名稱在畫圖前轉換。
- 錯誤訊息：`HttpRequest.js` 對 `resData.msg` 套 `t()`；字典收錄後端固定訊息（`BizException`、`ApiCodeEnum` 等）。帶動態參數的訊息查不到就顯示原文。
- 列表資料名稱：`translateListLabels()` 只轉「列表」回應（陣列或 `records`）裡的 `wayName`、`ifName`、`roleName`、`entName`、`configName`、`configDesc`、`groupName`、`methodRemark`、`agentName`，且只在字典有完全相同的鍵時才換。逐筆讀取（編輯表單）的回應不轉，避免把譯文存回資料庫。
- 使用者自行輸入的內容（商戶名稱、備註等）不翻譯；建立商戶時系統自動產生的應用名稱「預設應用」也屬於資料，不翻譯。

## 新增或修改畫面文字

1. 寫繁中原文並包在 `t()` / `$t()` 裡；需要插入變數時用 `t('共 {0} 筆', [n])`，不要用字串相加拼句子（各語言語序不同）。
2. 不要拿翻譯後的文字做判斷（例如 `label === '日期'`）；判斷用代碼或原始值。
3. 在 `src/i18n/locales/*.json` 為新鍵補上各語言翻譯；漏掉的鍵會顯示繁中原文，不會壞畫面。
4. 後端新增固定錯誤訊息或選單名稱時，同樣把繁中原文加進字典。
